EBM readiness

Which issued invoices carry everything EBM needs, and what the rest are missing.

EBM settings
No invoice here is fiscalised
An invoice is fiscalised when the RRA's signing device has signed it and returned a receipt. Nothing in this application sends an invoice anywhere, so no invoice has been signed and none carries a receipt. This page reports readiness only: whether an invoice holds the data EBM would require. Treating "ready" as "declared" is the one mistake that would matter here, because it would be a false statutory record shown to whoever later has to answer for the return.
Why this is worth doing before certification
EBM rejects an invoice for missing data one invoice at a time, after certification — by which point the invoices are issued and the gaps have to be chased back through customers who have moved on. The gaps are the same whichever way the integration is eventually built, so closing them now is work that is not wasted.
One gap cannot be fixed by editing invoices
EBM requires an RRA item classification code on every line, and there is no field for one anywhere on a product. A SKU is the business's own code and is not the same thing. That gap is not counted against individual invoices below, because no amount of editing them would close it — it needs a field on the product and the RRA's code list.
The business has no TIN recorded
Every invoice below is short of the seller's TIN for the same reason, so the count of incomplete invoices is really one problem repeated. Record it once under company settings and most of these will clear at a stroke.
